# Ⓐ Ansible Role: reboot

Reboots a Red Hat Enterprise Linux (RHEL) host with `ansible.builtin.reboot` and waits until a test command succeeds again, with configurable pre- and post-delays, timeout and broadcast message. It is the last stage of `site.yml`, where it exists so that a site run can finish with a controlled reboot after kernel updates or SCAP remediation, but only when explicitly asked: the collection playbook includes the role only when the `reboot` variable is true.

The role dispatches by OS family. Windows hosts are matched but the Windows task file contains no tasks yet, so they are skipped unchanged.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.reboot` when referencing this role.

## Requirements

- Managed node: RHEL 9 or 10 (or Fedora) reachable over SSH; the role escalates to root for the reboot itself.
- Collections used directly: none beyond `ansible.builtin`.
- No inventory groups are required; the collection playbook targets `all`.

## Example playbook

This matches the collection's own [`playbooks/reboot.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/reboot.yml):

```yaml
---

- name: Reboot
  hosts: "{{ target_hosts | default('all') }}"
  gather_facts: false
  become: true
  tags:
    - reboot
  tasks:
    - name: Reboot
      ansible.builtin.include_role:
        name: infra.soe.reboot
      when:
        - reboot | default(false) | bool
```

Run with `ansible-playbook infra.soe.site -e reboot=true -l satellite_server` to end a site run with a reboot of one group.

## Security considerations

- The reboot task runs with `become: true` and `become_user: root` regardless of the play settings.
- `reboot_test_command` is executed on the returning host as the connecting user; keep it to a harmless command such as `whoami`.

## Operational notes

- The role gathers the `distribution` fact itself, so plays can keep `gather_facts: false`.
- A host that does not answer within `reboot_timeout` seconds fails the task; raise the value for hosts with long firmware or storage initialisation.
- Windows support is a stub: the OS family is dispatched but no reboot is performed. Use `ansible.windows.win_reboot` directly until the task file is implemented.
