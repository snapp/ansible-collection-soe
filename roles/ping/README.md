# Ⓐ Ansible Role: ping

Confirms that Ansible can reach a host: it gathers the `distribution` fact and runs `ansible.builtin.ping`, or `ansible.windows.win_ping` on Windows. A successful run proves the transport, the credentials, privilege escalation where the play enables it and a working interpreter on the managed node. In the reference implementation it is the smoke test run against a freshly provisioned site before `site.yml`, and the job template operators reach for first when something is wrong with an inventory source or a credential in Red Hat Ansible Automation Platform (AAP).

The role is not part of `site.yml`; it has its own `ping` playbook that targets `all`.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.ping` when referencing this role.

## Requirements

- Managed node: Red Hat Enterprise Linux (RHEL) 9 or 10, Fedora or any other host with Python, or Windows with WinRM or SSH and PowerShell.
- Collections used directly: [`ansible.windows`](https://console.redhat.com/ansible/automation-hub/repo/published/ansible/windows/) (`win_ping`) for Windows hosts.
- No inventory groups are required.

## Example playbook

This matches the collection's own [`playbooks/ping.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/ping.yml):

```yaml
---

- name: Verify Ansible Connectivity
  hosts: "{{ target_hosts | default('all') }}"
  gather_facts: false
  become: false
  tags:
    - redhat
    - fedora
    - microsoft
    - ping
  roles:
    - infra.soe.ping
```

## Security considerations

- The role changes nothing on the managed node and needs no privilege escalation; the collection playbook runs it with `become: false`.
- The fact gathering is limited to the `distribution` subset.

## Operational notes

- Facts are gathered by the role (`!all`, `!min`, `distribution`), so the play can keep `gather_facts: false`.
- Unknown OS families fall back to `ansible.builtin.ping`, which requires Python on the target.
