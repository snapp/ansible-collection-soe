# Ⓐ Ansible Role: redhat_idm_acme

Enables or disables the Automatic Certificate Management Environment (ACME) service of a Red Hat Identity Management (IdM) server, together with its certificate pruning, so that the actual state matches `redhat_idm_acme_enabled`. ACME is the second way the reference implementation issues certificates from the IdM certificate authority: services on enrolled hosts use certmonger through `infra.soe.redhat_idm_service`, while containerised services such as the Caddy reverse proxy (`infra.soe.caddy`) request their certificates from the IdM ACME directory at `https://idm1.mtj1.prod.example.org/acme/directory`.

The role runs on an IdM server and is composed by `infra.soe.redhat_identity_management` during its configure stage, once per site.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.redhat_idm_acme` when referencing this role.

## Requirements

- Managed node: a Red Hat Enterprise Linux (RHEL) 9 or 10 IdM server with the `ipa-acme-manage` command (part of `ipa-server`) and the integrated IdM certificate authority.
- Collections used directly: none beyond `ansible.builtin` (`uri`, `command`).
- The host must be in the `idm_server` group when used through `infra.soe.redhat_identity_management`.

## Dependencies and composition

The role composes nothing. It is composed by [`redhat_identity_management`](https://github.com/snapp/ansible-collection-soe/blob/main/roles/redhat_identity_management/README.md) through `import_role` with no variables passed; `redhat_idm_acme_enabled` is read from inventory.

## Tags

The role defines no tags. `redhat_identity_management` applies `idm_acme` and `idm_configure` to it.

```yaml
  hosts: "{{ target_hosts | default('idm_server') }}"

```

## Security considerations

- Enabling ACME lets any host that can reach the IdM server on port 443 and prove control of a DNS name in the IdM domain obtain a certificate for it (HTTP-01 and DNS-01 challenges). That is intended for the reverse proxy and container hosts; disable it on sites where every certificate must go through certmonger and an enrolled host identity.
- The state probe uses `validate_certs: false` because it may run before the IdM CA is trusted by the controller; it reads only the HTTP status.
- `ipa-acme-manage` runs as root on the IdM server.

## Operational notes

- The role is idempotent: `ipa-acme-manage` runs only when the probed state (HTTP 200 on the directory URL means enabled) differs from the desired one.
- ACME clients must use the RSA key type with IdM's ACME; Caddy's default ECDSA keys are rejected, which is why the Caddy site blocks in this collection set `key_type rsa4096`.
- Pruning is toggled together with the service; it removes expired ACME certificates from the CA database on a schedule.
