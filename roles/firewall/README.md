# Ⓐ Ansible Role: firewall

Configures the host firewall in four layers: firewalld zones and services through `redhat.rhel_system_roles.firewall`, firewalld policy objects for traffic between firewalld zones, the `LogDenied` setting that makes firewalld log rejected packets, and an nftables table of "quiet drops" that discards known-benign noise (for example multicast discovery on a management network) before firewalld would log it. It is the one place in the collection where host filtering is expressed, which is why every product role includes it with its own port list rather than opening ports itself.

In the `site.yml` build order the standalone `firewall` playbook runs second to last, after every service has declared its ports, and applies the site-level definitions from inventory to all Red Hat Enterprise Linux (RHEL) and Fedora hosts. Earlier in the sequence the product roles (`redhat_identity_management`, `redhat_satellite`, `redhat_keycloak`, `redhat_ansible_automation_platform`, `caddy`, `netbird`, `application_server`) include this role to open their own ports. The master switch `firewall_enabled` defaults to false, so a host is never filtered just because the role touched it.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.firewall` when referencing this role.

## Requirements

- Managed node: RHEL 9 or 10, or Fedora, with `firewalld` installed. The quiet-drops layer additionally needs the `nftables` package and expects `/etc/sysconfig/nftables.conf` to exist.
- Collections used directly: [`redhat.rhel_system_roles`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/rhel_system_roles/content/role/firewall/) (`firewall` role).
- No inventory groups are required. The collection playbook targets `redhat:fedora`.

## Example playbook

This matches the collection's own [`playbooks/firewall.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/firewall.yml):

```yaml
---

- name: Firewall
  hosts: "{{ target_hosts | default('redhat:fedora') }}"
  gather_facts: false
  become: true
  tags:
    - redhat
    - fedora
    - firewall
  roles:
    - infra.soe.firewall
```

Site-level definitions for a group, in `group_vars`:

```yaml
firewall_enabled: true
firewall_log_denied: all

firewall:
  - previous: replaced
  - zone: soe
    state: present
    permanent: true
  - zone: soe
    service:
      - dhcpv6-client
      - ssh
    state: enabled
    permanent: true
  - set_default_zone: soe
    state: enabled
    permanent: true

firewall_policies:
  - name: soe-to-external
    ingress_zones: [soe]
    egress_zones: [external]
    target: ACCEPT

firewall_quiet_drops:
  - name: mDNS and SSDP discovery on the management network
    proto: udp
    dport: [5353, 1900]
    daddr: 10.1.10.0/24
```

## Security considerations

- Policies are validated before anything is written: a well-formed name, non-empty ingress and egress firewalld zones, a known target and a known state. `firewall_log_denied` is validated against firewalld's accepted values.
- Quiet drops are terminal: matching packets are discarded, not merely kept out of the log. Anything listed there is unreachable on that host. The table hooks at nftables priority `filter`, before firewalld's `filter + 10`.
- Files are written as root: `/etc/nftables/quiet-drops.nft` with mode `0600`, `/etc/firewalld/policies` with `0750` and each policy file with `0644`. Any `flush ruleset` line is removed from `/etc/sysconfig/nftables.conf` so that firewalld's own tables survive an nftables restart.
- `firewall_enabled: false` (the default) leaves the host exactly as it was. Setting `previous: replaced` in `firewall` makes inventory the single source of truth and removes rules added by hand.

## Operational notes

- `firewall` is passed through untouched and not defaulted here, so the system role's defaults apply when a site sets nothing; its schema (zones, services, ports, rich rules, `set_default_zone`, `previous: replaced`) is documented upstream.
- `firewall_log_denied` is only written when defined; defaulting it would rewrite `firewalld.conf` on every run.
- The role is idempotent: `lineinfile` and `template` tasks only notify the `Reload firewalld` and `Reload nftables` handlers on change. A policy with `state: absent` removes its file and reloads firewalld.
- Product roles set `<role>_firewall_enabled: true` by default, so including a product role does enable filtering on that host with that role's ports; set the role-specific switch to false to opt out, or `firewall_enabled: false` only affects the standalone run.
- The term zone is overloaded: this role deals in firewalld zones. DNS zones belong to `redhat_identity_management`, network zones (`10.<site>.<zone>.0/24`) to the site inventory.
