# netbird

Deploys a self-hosted [NetBird](https://netbird.io) mesh-VPN control plane as
**rootless Podman Quadlets**, with Red Hat Build of Keycloak (RHBK) registered as an
external OIDC connector behind NetBird's embedded IdP (Dex). The stack runs as a
dedicated rootless IdM user (`netbird`), in the same style as the `caddy` and
`ai_webui` roles.

> **NOTE|2026-08-13** This role previously deployed four containers
> (`management`/`dashboard`/`signal`/`coturn` + network) wired directly to Keycloak.
> NetBird's architecture moved to an embedded Dex IdP that brokers external OIDC
> providers rather than letting the dashboard talk to them directly; the old direct
> wiring stopped working once the deployment (unpinned, on `:latest`) picked up that
> change. This role now follows NetBird's current combined-server model, confirmed
> against upstream's `infrastructure_files/getting-started.sh` install script.

## Components

| Quadlet unit | Image | Role |
|---|---|---|
| `netbird.network` | — | Isolated bridge network shared by both containers |
| `netbird-server.volume` | — | Persists the SQLite store + keys |
| `netbird-server.container` | `netbirdio/netbird-server` | Management + signal + relay + embedded STUN + embedded IdP (Dex), all on one internal port |
| `netbird-dashboard.container` | `netbirdio/dashboard` | Web UI — authenticates against netbird-server's own embedded Dex issuer, not RHBK directly |

TLS is terminated by the **`caddy`** role using the Let's Encrypt **DNS-01** challenge
for `netbird.ite.example.org`. See [`files/caddy_netbird.conf`](files/caddy_netbird.conf)
for the site block to add to `caddy_domains`.

## Prerequisites

1. **IdM service user** with linger enabled:
   ```bash
   ipa user-add netbird --shell=/sbin/nologin --home=/var/lib/netbird
   loginctl enable-linger netbird
   ```
2. **One RHBK client**, confidential (not the old public-PKCE `netbird` client):
   - `netbird` — confidential client (`client_authenticator_type: client-secret`),
     single redirect URI. That URI is **generated by NetBird's own dashboard** the
     first time RHBK is added under Settings → Identity Providers — it is not a
     fixed, guessable path. Deploy first, capture that URL, then update the client's
     `redirect_uris` to match.
   - The `groups` protocol mapper is still required (NetBird's JWT group sync reads
     the `groups` claim). The old `netbird-backend` confidential client and its
     `view-users`/`query-groups` service-account grant are **no longer needed** — group
     membership now arrives via the ID token, not an admin-API sync.
   - The dashboard itself always authenticates against NetBird's own embedded Dex
     issuer using a fixed internal client id (`netbird-dashboard`) — this has nothing
     to do with the RHBK client above. Don't confuse the two.
3. **Caddy image** built with the `caddy-dns/cloudflare` plugin and a
   `CLOUDFLARE_API_TOKEN` (Zone.DNS:Edit) supplied as a Podman secret/env var.

## Registering RHBK as an identity provider

The role registers RHBK as a NetBird identity-provider connector automatically via
`POST /api/identity-providers`, using an admin Personal Access Token minted through
`netbird-server`'s own CLI (`netbird-server admin token create`, the same mechanism
upstream's installer uses to bootstrap its proxy component) — no manual dashboard
login required. The token is cached at
`{{ netbird_config_dir }}/.admin_api_token` (mode `0600`) so repeat runs don't mint a
new one every time.

After the connector is registered:

1. Log in to the dashboard via RHBK and confirm you land on `/peers` without the
   spinner hang this migration fixed.
2. Settings → Identity Providers will show the RHBK connector and the redirect URI
   NetBird generated for it — copy that into the RHBK `netbird` client's
   `redirect_uris` if it isn't there already (see Prerequisites above).
3. Settings → Groups → enable JWT group sync with claim `groups`.
4. Only once SSO login is confirmed working, set `netbird_local_auth_disabled: true`
   and re-run the role to disable local/password login.

## Secrets (supply via AAP credential injectors as extra_vars — never commit)

| Variable | How to generate |
|---|---|
| `netbird_datastore_encryption_key` | `openssl rand -base64 32` |
| `netbird_relay_secret` | `openssl rand -base64 32` (used as `server.authSecret`) |
| `netbird_session_cookie_key` | `openssl rand -base64 32` |
| `netbird_idp_client_secret` | RHBK → `netbird` client → Credentials |

The role renders `config.yaml` and `dashboard.env` with these values into
`/var/lib/netbird/config` (mode `0600`, `container_file_t`, `no_log: true`). They are
never written to job output and never enter the repo.

## Usage

```yaml
- name: Deploy NetBird
  hosts: ite
  tasks:
    - name: NetBird mesh VPN
      ansible.builtin.include_role:
        name: infra.apps.netbird
```

Run with secrets injected by AAP, or for a local PoC:

```bash
ansible-playbook playbooks/deploy_netbird.yml \
  -e netbird_relay_secret=... \
  -e netbird_datastore_encryption_key=... \
  -e netbird_session_cookie_key=... \
  -e netbird_idp_client_secret=...
```

> **NOTE** Override `netbird_domain` and `netbird_idp_issuer` in `group_vars` for your
> environment. `netbird_server_image` / `netbird_dashboard_image` are pinned to a
> matched release pair — bump them together, deliberately, never let either float on
> `:latest`.
