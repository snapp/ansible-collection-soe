# Ⓐ Ansible Role: application_server

Prepares a host to run containerised services: it installs Podman on Red Hat Enterprise Linux (RHEL) or Fedora, layering the packages with `rpm-ostree` on image-based systems and rebooting once when the layer changed, and opens HTTP and HTTPS through its dependency on `infra.soe.firewall`. The result is the workload host of the reference implementation, onto which the rootless Quadlet roles (`infra.soe.caddy`, `infra.soe.netbird`) and any further self-hosted application are deployed as unprivileged service accounts.

In the `site.yml` build order this is the last host stage, after Red Hat Ansible Automation Platform (AAP) and RHEL image builder and before the site-wide firewall and reboot passes. It assumes the host is registered (`infra.soe.redhat_register`) so the Podman packages resolve, and that it is enrolled in Red Hat Identity Management (IdM) when the services on it use IdM service accounts.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.application_server` when referencing this role.

## Requirements

- Managed node: RHEL 9 or 10, or Fedora, including rpm-ostree variants. The rpm-ostree path needs `community.general.rpm_ostree_pkg`.
- Collections used directly: [`community.general`](https://docs.ansible.com/ansible/latest/collections/community/general/index.html) (`rpm_ostree_pkg`); through the dependency, [`redhat.rhel_system_roles`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/rhel_system_roles/) (`firewall`).
- Inventory group `application_server` (the collection playbook's default target).

## Example playbook

This matches the collection's own [`playbooks/application_server.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/application_server.yml):

```yaml
---

- name: Application Server
  hosts: "{{ target_hosts | default('application_server') }}"
  gather_facts: false
  become: true
  tags:
    - redhat
    - fedora
    - app_server
  roles:
    - infra.soe.application_server
```

## Security considerations

- The default firewall definition opens 80/tcp and 443/tcp on the host. Services that need other ports declare them in their own role (for example `netbird_firewall`); narrow or replace `application_server_firewall` for hosts that do not serve HTTP.
- On rpm-ostree systems the role also layers `acl`, which `become` to an unprivileged user requires to set file ACLs on temporary files, and `python3-rpm`, which `redhat.rhel_system_roles.podman` needs for `package_facts`.
- The role does not create service accounts or configure Podman itself; rootless users, lingering and quadlets are the responsibility of the application roles.

## Operational notes

- The rpm-ostree path reboots the host immediately after a changed `rpm-ostree install`, inside this role, because layered packages are only available after a reboot. Non-ostree hosts are never rebooted here.
- Idempotent: `dnf` and `rpm_ostree_pkg` report no change when Podman is present; the ostree detection reads `/run/ostree-booted`.
- `--tags podman` installs Podman on non-ostree hosts only; use the play tag `app_server` to run the whole role.
