# Ⓐ Ansible Role: redhat_image_builder

Installs RHEL image builder (`osbuild-composer`, `composer-cli` and the Cockpit web interface), enables its services, grants the designated users access through the `weldr` group and, on a host registered to Red Hat Satellite, replaces osbuild-composer's Red Hat CDN repository definitions with repositories served from Satellite content views, trusting the Satellite CA for RHSM-protected content. When a Red Hat Identity Management (IdM) administrator password is available it also creates the `imagebuilder-users` group and the HBAC rule that lets its members reach the host, and it applies the Image Builder CIS tailoring through `infra.soe.redhat_scap`.

Image builder is where the hardened golden images of the reference implementation are composed. Building from a Satellite content view promoted to a lifecycle environment, rather than from whatever the CDN serves today, is what makes an image reproducible and ties it to the same promoted content the running hosts receive. The role targets the `image_builder` group and runs after Red Hat Ansible Automation Platform (AAP) in `site.yml`; the images it produces feed the provisioning pipeline that creates the next hosts.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.redhat_image_builder` when referencing this role.

## Requirements

- Managed node: Red Hat Enterprise Linux (RHEL) 9 or 10 (the package set differs: `cockpit-image-builder` on RHEL 10, the Cockpit-shipped composer plugin on RHEL 9), registered to Satellite (`infra.soe.redhat_register`) so that `/etc/rhsm/ca/katello-server-ca.pem` exists and the repository rewrite applies, with generous storage under `/var/cache` and `/var/lib/osbuild` (`infra.soe.local_storage`).
- Collections used directly: none beyond `ansible.builtin`; through composed roles, [`redhat.rhel_idm`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/rhel_idm/).
- Inventory group `image_builder`; an `idm_server` group when the IdM stages run.
- The Satellite must publish the RHEL content views whose paths `redhat_image_builder_satellite` and `redhat_image_builder_repositories` point at.

## Security considerations

- Members of `weldr` can compose and download images that contain whatever the blueprint says, including credentials baked into them; keep `redhat_image_builder_users` to the people who build golden images.
- The role replaces `/etc/rhsm/ca/redhat-uep.pem` with the Satellite CA so that osbuild-composer's RHSM-authenticated fetches trust the Satellite; content therefore comes only from the Satellite, never from the CDN, once the rewrite has happened.
- Cockpit, `httpd` and `firewalld` are enabled on the host. Cockpit serves the Image Builder web interface, which is why the shipped CIS tailoring deselects the rule that disables Cockpit; the justification is in [`vars/scap/cis.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/roles/redhat_image_builder/vars/scap/cis.yml).
- The role opens no firewall ports itself; reach the web interface through the site reverse proxy or open the Cockpit port in the site's `firewall` definitions.

## Operational notes

- The repository rewrite runs only when the Satellite CA is present on the host and `redhat_image_builder_repositories` is defined; a host registered directly to Red Hat Subscription Management keeps the CDN definitions.
- The default repositories cover RHEL 8, 9 and 10 at `<baseurl>/<organization>/<lifecycle_environment>/rhel/content/dist/rhel<N>/<N>/x86_64/{baseos,appstream}/os`, which assumes a content view labelled `rhel`; override `redhat_image_builder_repositories` for a different content view layout.
- `osbuild-composer` is restarted by handler when the CA or a repository definition changes; running composes are interrupted.
- `redhat_image_builder_packages` comes from `vars/RedHat.yml` and `vars/RedHat_9.yml` and is not an input; RHEL 9 lacks the `cockpit-image-builder` package.
- `weldr` membership is applied with `gpasswd` and reported as changed only when the user was not yet a member.
