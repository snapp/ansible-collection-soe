# Ⓐ Ansible Role: bootstrap

Loads one vaulted variable file per inventory group of the current host from a directory in the site repository, `<bootstrap_directory>/<group>.vault.yml`, and skips groups that have none. This is the day-0 escape hatch of the reference implementation: before Red Hat Identity Management (IdM) exists, hosts are reached with a local bootstrap account whose password and other first-run secrets must come from somewhere, and that somewhere is a vaulted file per group that never enters `group_vars`. Once IdM is up, `infra.soe.redhat_identity_management` removes the bootstrap account and the files are no longer needed.

The role is not part of `site.yml`; a site playbook includes it before the first stage and enables it with `-e bootstrap=true` for the initial run. The only task runs on the control node (`include_vars`); nothing is changed on the managed host.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.bootstrap` when referencing this role.

## Requirements

- Control node: the vault password for the `.vault.yml` files (`--vault-id` or `ANSIBLE_VAULT_PASSWORD_FILE`).
- Managed node: none. The role performs no remote action and can be included for any inventory host.
- No inventory groups are required; the file names follow whatever groups the host belongs to.

## Dependencies and composition

None. The role composes nothing and is composed by nothing in the collection.

## Tags

The role defines no tags. Include it with `tags: always` from the site playbook so that tag-filtered runs still receive the bootstrap variables.

## Example playbook

```yaml
---

- name: Load Host Group bootstrap variable files
  hosts: all
  gather_facts: false
  become: false
  tags: always
  vars:
    bootstrap_directory: "{{ playbook_dir }}/bootstrap"
  tasks:
    - name: Check for bootstrap mode
      ansible.builtin.include_role:
        name: infra.soe.bootstrap
      when:
        - bootstrap | default(false) | bool
```

With a site layout of `playbooks/bootstrap/all.vault.yml`, `playbooks/bootstrap/redhat.vault.yml` and `playbooks/bootstrap/identity_management.vault.yml`, a host in the `redhat` and `identity_management` groups receives the variables from all three files, loaded in sorted group order.

## Security considerations

- The files are expected to be Ansible Vault encrypted; the role does not check that they are. Keep them out of `group_vars` and out of any directory that is synchronised to a managed host.
- Variables loaded with `include_vars` have a high precedence and stay defined for the rest of the play; a bootstrap password therefore remains in memory of the controller process until the play ends.
- The task registers its result in `bootstrap_vars`, which contains the loaded values; do not print it.

## Operational notes

- Files are loaded in sorted group order (`group_names | sort`), so a later group overrides an earlier one for the same key.
- `bootstrap_directory` has no default and the include fails without it; set it at play level as in the example.
- Because the role is gated on `bootstrap`, leaving the include in a site playbook permanently costs nothing on normal runs.
