# Ⓐ Ansible Role: redhat_update

Updates every installed package on a Red Hat Enterprise Linux (RHEL) host with `dnf` and, when enabled, reboots the host through a handler at the end of the play if anything changed. The role is off by default: nothing happens until `redhat_update_enabled` is true for a group or host, which keeps the update stage of `site.yml` an explicit decision. On a Satellite-registered host the visible package versions come from the content view promoted to that host's lifecycle environment, so this role is the last step of a patch cycle that starts with publishing and promoting content in `infra.soe.redhat_satellite`.

In the `site.yml` build order the update stage runs fourth, after local users, registration and storage and before Red Hat Identity Management (IdM) is installed. The collection playbook excludes the `satellite` group, whose updates follow the Satellite upgrade procedure instead.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.redhat_update` when referencing this role.

## Requirements

- Managed node: RHEL 9 or 10 registered for content (`infra.soe.redhat_register`).
- Collections used directly: none beyond `ansible.builtin`.
- No inventory groups are required; the collection playbook targets `redhat:!satellite`.

| `redhat_update_reboot_enabled` | bool | no |  | Reboot the host at the end of the play when the update changed something. Unset behaves as false. |

## Dependencies and composition

None. The reboot is performed by this role's own handler, not by `infra.soe.reboot`.

## Tags

The role defines no tags. The collection playbook adds the play tags `redhat` and `update`.

## Example playbook

This matches the collection's own [`playbooks/redhat_update.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/redhat_update.yml):

```yaml
---

- name: Update Red Hat Enterprise Linux (RHEL)
  hosts: "{{ target_hosts | default('redhat:!satellite') }}"
  gather_facts: false
  become: true
  tags:
    - redhat
    - update
  roles:
    - infra.soe.redhat_update
```

Enable it for a patch window with extra variables rather than permanently in inventory:

```console
ansible-playbook infra.soe.redhat_update -l app1.mtj1.prod.example.org -e redhat_update_enabled=true -e redhat_update_reboot_enabled=true
```

## Security considerations

- The update applies every available advisory from the enabled repositories; the set of advisories is controlled upstream by the content view, not by this role.
- With `redhat_update_update_only` left at its fallback of true, no new packages are installed, which keeps the installed footprint of a hardened image unchanged.
- The reboot handler runs with the play's privileges at the end of the play; services that cannot tolerate an unplanned restart should not have `redhat_update_reboot_enabled` set in inventory.

## Operational notes

- `dnf` with `name: '*'` and `state: latest` is idempotent and reports a change only when packages were updated; the reboot handler fires only on that change and only when `redhat_update_reboot_enabled` is true.
- The handler reboots with the `ansible.builtin.reboot` defaults; tune delays and timeouts by using `infra.soe.reboot` afterwards instead if the host needs them.
- Because there is no `defaults/` file, inventory must set the variables explicitly; `ansible-doc -t role infra.soe.redhat_update` lists the fallbacks.
