# Ⓐ Ansible Role: redhat_idm_hbac

Creates or updates host-based access control (HBAC) rules in Red Hat Identity Management (IdM) with `redhat.rhel_idm.ipahbacrule`. HBAC is how the reference implementation decides who may log in where: each product role brings a rule that lets its administrator and user groups reach its host (`allow_satellite`, `allow_keycloak`, `allow_ansible_automation_platform`, `allow_image_builder`), and `infra.soe.redhat_identity_management` manages the site-wide rules such as the one that lets the automation account and site administrators reach every host.

The role is composed right after IdM is installed and again by each product role as the product is deployed.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.redhat_idm_hbac` when referencing this role.

## Requirements

- Managed node: a Red Hat Enterprise Linux (RHEL) 9 or 10 host that is an IdM server or an enrolled client with the IdM Python libraries, because the `redhat.rhel_idm` modules run on the target.
- Collections used directly: [`redhat.rhel_idm`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/rhel_idm/) (`ipahbacrule`).
- An IdM administrator password in `redhat_idm_hbac_admin_password`. Groups referenced by a rule must exist (`infra.soe.redhat_idm_groups`).

## Example playbook

```yaml
---

- name: Red Hat Identity Management (IdM) HBAC rules
  hosts: "{{ target_hosts | default('idm_server') }}"
  gather_facts: false
  become: true
  roles:
    - role: infra.soe.redhat_idm_hbac
      redhat_idm_hbac_admin_password: "{{ idm_admin_password }}"
      redhat_idm_hbac_rules:
        - name: allow_admins_everywhere
          description: Site administrators and the automation account may log in to any host
          hostcategory: all
          servicecategory: all
          users:
            - ansible
          groups:
            - admin-accounts
        - name: allow_satellite
          description: Satellite administrators and users may log in to the Satellite server
          servicecategory: all
          groups:
            - satellite-admins
            - satellite-users
          hosts:
            - sat1.mtj1.prod.example.org
```

## Security considerations

- IdM ships an enabled `allow_all` HBAC rule. The rules this role creates only matter once that rule is disabled (`ipa hbacrule-disable allow_all`), which the collection does not do for you; the site is expected to disable it after the automation account's own rule exists, or every host stays open to every user.
- The administrator password is passed as `ipaadmin_password`; the task runs under `no_log` (gated by `no_log_enabled`), which also hides the rule definitions.
- Rules are only ever ensured present; stale rules must be removed by hand.

## Operational notes

- A rule with neither `hosts` nor `hostcategory: all` matches no host; the same holds for users and services. Keep the three category keys explicit.
- Service account logins (for example the Ansible user used by Red Hat Ansible Automation Platform (AAP)) need an HBAC rule like any other user; the site-wide rule in the example covers it.
- `ipa hbactest` on an IdM server is the quickest way to confirm what a rule set allows for a given user, host and service.
