# Ⓐ Ansible Role: redhat_register

Registers a Red Hat Enterprise Linux (RHEL) host for content: it prepares `/etc/rhsm`, records the Satellite location as a subscription-manager fact, installs the Satellite CA consumer package, registers through `redhat.rhel_system_roles.rhc` (activation keys, repositories and Red Hat Insights come from that role's `rhc_*` inventory variables) and assigns the host to a Satellite host group with `redhat.satellite.host`. When `rhc_server.hostname` points at `subscription.rhsm.redhat.com` the Satellite steps are skipped and the host registers directly with Red Hat Subscription Management, which is how the Satellite server itself is registered before Satellite exists.

Registration is the second stage of `site.yml`. Everything after it installs packages, and on a Satellite-registered host those packages come from the content view the activation key selects, which is how the reference implementation gates builds on promoted content rather than on whatever the CDN serves today.

> [!NOTE]
> Use the Fully Qualified Collection Name `infra.soe.redhat_register` when referencing this role.

## Requirements

- Managed node: RHEL 9 or 10 with network access to the Satellite (ports 80 and 443) or to the Red Hat CDN.
- Collections used directly: [`redhat.rhel_system_roles`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/rhel_system_roles/content/role/rhc/) (`rhc` role), [`redhat.satellite`](https://console.redhat.com/ansible/automation-hub/repo/published/redhat/satellite/content/module/host/) (`host` module).
- Inventory: the `rhc_*` variables of the rhc role (`rhc_state`, `rhc_server`, `rhc_baseurl`, `rhc_organization`, `rhc_auth` with activation keys, `rhc_repositories`, `rhc_insights`) and the shared `satellite_*` variables below. The collection playbook targets the `redhat` group.
- On the Satellite path: a Satellite with the activation key, host group and location already defined (`infra.soe.redhat_satellite`), and an API user allowed to edit hosts.

## Example playbook

This matches the collection's own [`playbooks/redhat_register.yml`](https://github.com/snapp/ansible-collection-soe/blob/main/playbooks/redhat_register.yml):

```yaml
---

- name: Red Hat Enterprise Linux (RHEL) registration via Red Hat Subscription Management (RHSM)
  hosts: "{{ target_hosts | default('redhat') }}"
  gather_facts: false
  become: true
  tags:
    - redhat
    - register
  roles:
    - infra.soe.redhat_register
```

Satellite registration for the `redhat` group, in `group_vars/redhat/redhat_register.yml`:

```yaml
satellite_location: mtj1
satellite_organization: Example
satellite_activation_keys:
  - prod-rhel10-server
satellite_host_group: prod/rhel10/server
satellite_hostname: sat1.mtj1.prod.example.org
satellite_server_url: "https://{{ satellite_hostname }}"
satellite_username: "{{ _vault_satellite_username }}"
satellite_password: "{{ _vault_satellite_password }}"
satellite_validate_certs: true

rhc_state: present
rhc_server:
  hostname: "{{ satellite_hostname }}"
  port: 443
  prefix: /rhsm
  insecure: false
rhc_baseurl: "https://{{ satellite_hostname }}/pulp/content"
rhc_organization: "{{ satellite_organization }}"
rhc_auth:
  activation_keys:
    keys: "{{ satellite_activation_keys }}"
rhc_insights:
  state: present
```

The Satellite server itself uses `rhc_server.hostname: subscription.rhsm.redhat.com`, `rhc_baseurl: https://cdn.redhat.com` and the Red Hat CDN repositories.

## Security considerations

- The CA consumer package is downloaded over plain HTTP from the Satellite with GPG verification disabled, as the package is what establishes trust in the Satellite CA in the first place. The first registration therefore trusts the network path to the Satellite; register over a trusted network zone or pre-stage the CA from the golden image.
- `satellite_password` is passed to the `redhat.satellite.host` module, which marks its `password` parameter `no_log`; keep the value in Ansible Vault or an AAP credential injector.
- `/etc/rhsm`, `/etc/rhsm/ca` and `/etc/rhsm/facts` are created with mode `0755` and the `rhsmcertd_config_t` SELinux type; `location.facts` is `0644`.
- Activation keys decide which content view, lifecycle environment and host collections a host receives; treat them as part of the host's trust boundary and keep them out of logs.

## Operational notes

- `rhc_server` is read before the rhc role runs, so it must be defined in inventory; the role fails at the first conditional otherwise.
- The host group assignment runs on every pass and is idempotent; changing `satellite_host_group` in inventory moves the host on the next run.
- The Katello CA consumer package is slated to disappear upstream; the role still relies on it, which is tracked in the code.
- Registration against Satellite requires the activation key and host group to exist; run `infra.soe.redhat_satellite` first, or register the Satellite server itself against Red Hat Subscription Management.
- Re-running with a changed `rhc_auth` re-registers through the rhc role; see its documentation for `rhc_state: reconnect`.
